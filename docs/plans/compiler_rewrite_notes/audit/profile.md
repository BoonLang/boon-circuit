## subsystem
CPU attribution of the whole compiler pipeline (release boon_cli compiler-sample, fresh-process), covering counter, TodoMVC and NovyWave in diagnostics and verified modes
## purpose_summary
perf_event_paranoid is 2, so samply cannot run and I did not change the setting. I got full-stack sampled profiles another way: a gdb/MI sampler (tools/gdbprof.py) that starts boon_cli as its own child (ptrace_scope=1 allows that), interrupts it with SIGINT at random 1-5 ms intervals, and unwinds each stop through .eh_frame. That gave 453 to 2,078 compile-phase samples per cell over 5 to 80 runs. Two checks support the sampler: per-phase sample shares match the product's own phase timers to within 1 percentage point (TodoMVC verified typecheck 55.5% vs timer 55.0%, semantic 19.7% vs 20.2%, backend 11.5% vs 11.0%, plan validation 11.1% vs 11.4%; NovyWave semantic 42.4% vs 41.7%, typecheck 37.8% vs 38.0%), and schedule_variable reproduces as the top self-time function, as in the samply evidence file. Main findings: (1) SHA-256 plus CBOR canonical hashing takes 25.1% of TodoMVC verified, 30.8% of NovyWave verified, 39% of counter verified, 11.7% of NovyWave diagnostics and 4.4% of TodoMVC diagnostics. That is roughly 200 ms and 590 ms of pure self-proof on the verified path. The biggest consumers are plan_sha256 inside verify_plan (10.3% of TodoMVC verified), the semantic execution-image receipts and handoff (8.6% of NovyWave verified; the trace shows payload_hash 76 ms plus row_hash 53 ms), kernel receipts, fingerprints and term proofs (6.0%), dependency manifest V7 (4.6%) and the checked-image handoff (4.0%). The CPU (i7-9700K) has no SHA-NI, so SHA-256 runs at about 370 MB/s. (2) Diagnostics are bound by the kernel solver: KernelSession::check is 86.7% of TodoMVC diagnostics (solve 70.7%, per-call-path program construction 16.0%). schedule_variable alone is still 18.8% self time even with the T1a epoch fix, because it enumerates the whole equivalence class on every bind before checking the seen-stamp (solver.rs:4088-4093). (3) NovyWave diagnostics spend 23.4% in adapter projections before the kernel even starts: prepare_kernel_project_projection 16.0% (compact_owner_view 10.8%) and KernelProjectInput::new_with_abi 7.4%. (4) Counter's fixed cost is mostly incidental. 41% of counter diagnostics (about 3.0 ms) goes to loading and fully validating examples/manifest.toml on every compile (toml parse plus about 1,316 readlink syscalls from canonicalize) just to find the file list. About 1 ms rebuilds the builtin owner-ABI environment and SHA-256-hashes it. The real type solve is about 1.5% (about 0.1 ms). (5) Synthetic scaling shows three real superlinear hazards: static-branch-count about n^2.5 (TypeTermArena::variant_set_with_order, 86% self), call-depth about n^1.9 (DirectSummaryPlanCompiler plus a linear CallableSurface find), and contextual-call-site-count about n^1.8 (boon_typecheck::expr_contains_expr_id_seen). Linked operations grow linearly in all three. (6) Removing everything that is plainly incidental (hashing, re-validation, manifest, quadratic scans, Debug-string sort keys) would save about 34% of TodoMVC verified and 46% of NovyWave verified. It would save only about 14% of TodoMVC diagnostics (400 to about 343 ms against a 75 ms budget), so the solver architecture is the binding constraint for diagnostics.
## essential_work
- Lexing and AST construction: measured at 20-27% of the parse phase, about 4 ms for TodoMVC (3,576 lines) and about 17 ms for NovyWave (11,926 lines). That is about 0.7-1M lines/s, already near the reference rate.
- Name/module resolution across the 8 source units, including namespace assembly.
- Type inference over about 4,081 (TodoMVC) and 15,650 (NovyWave) checked expressions, with records, tag unions, LIST, HOLD/LATEST/THEN/WHEN and polymorphic FUNCTIONs. Principal types per definition plus call-site instantiation is the essential part. Per-call-path re-solving (10,537 compiled call sites from 352 checked calls on TodoMVC) is not.
- Producing user diagnostics with spans. present_kernel_project_diagnostics measured only 0.6 ms (TodoMVC) and 2.0 ms (NovyWave) via BOON_COMPILER_PHASE_TRACE.
- Reactive dataflow derivation: sources, states, pulses, dependencies. BOON_SEMANTIC_TRACE puts build_semantic_reactive_graph at 7 ms on TodoMVC and 42 ms on NovyWave.
- Lowering the typed program to the MachinePlan: scalar slots, list storage, derived values, the document/view plan.
- One identity for the final plan, computed once and only if a consumer needs it (cache key or export). It does not need to be SHA-256 inside the compile loop.

## algorithmic_problems
- problem: schedule_variable walks the whole equivalence class on every bind before any seen-check | evidence: solver.rs:4086-4131. Lines 4088-4093 push every member of equivalence_head[root] into schedule_stack unconditionally, and only then check reschedule_seen. With 154,284 mutations on TodoMVC this is 18.8% self time of TodoMVC diagnostics (about 75 ms) and 10.3% of TodoMVC verified, even with the T1a epoch stamp in place. | complexity: O(class size) per bind, so O(binds x class size) overall. The work is effectively quadratic in the size of large unified record classes. | fix: Stamp the root, not the members: if root is seen in this epoch, return before enumerating. Better still, keep consumers and dependents aggregated at the union-find root (merge the lists on union) so a bind visits one list.
- problem: variant_set_with_order: linear position scan per incoming variant, and the whole set is rebuilt, sorted and re-interned on every merge | evidence: term.rs:1455-1495. Synthetic static-branch-count typecheck: 800 gives 87 ms, 3200 gives 2,857 ms (32.8x for 4x input) while activations grow linearly (4,012 to 16,012). The function is 86.1% self time at n=3200. ## from_scratch_design
Pipeline, sized by what the profile shows is essential. (1) Source loading: the caller passes the file list, and the compiler never reads examples/manifest.toml. (2) Parser: a hand-written lexer and parser producing a flat, arena-indexed AST (u32 node ids in a struct-of-arrays layout), with a per-unit interned symbol table. Identity is (unit, node index). Stable edit-surviving identity, if needed at all, is computed lazily from a cheap structural hash (xxh3/FxHash), never SHA-256 per expression. Validation runs inside the parse walk. Target: the measured lex/AST share, about 4 ms TodoMVC and about 17 ms NovyWave, and no more. (3) Resolution: one pass producing a dense DefId per top-level definition and a call graph, then Tarjan SCCs. (4) Typing: HM-style inference with row-polymorphic records and tag-union types, solved per SCC in topological order. Structures: a global hash-consed type store (u32 TypeId; one Vec of nodes plus a FxHashMap for dedup; field names are symbol ids; tag sets are sorted small vectors or bitsets), union-find with path halving and rank for type variables, and per-root dependent lists merged on union, so no class enumeration. Generalize once per definition. Instantiate at each call site by substituting over the scheme's quantified variables, which costs O(scheme size) and never re-solves the callee. Selector-dependent refinement (THEN/WHEN arms narrowed by static tags) is a second, demand-driven pass over only the definitions that need it, memoized on (DefId, argument type ids). Authored field order goes in a side table keyed by record-literal node, not in type identity. Budget: about 10 constraints per expression at about 100-200 ns each. (5) One typed HIR carries types as TypeIds straight into dataflow lowering, with no checked-image re-encoding, no second type representation (boon_checked::Type with String field names), and no Debug-string ordering. (6) Semantic/reactive derivation and plan lowering: one pass building the reactive graph over dense ids, then emitting the MachinePlan, with functions shared rather than inlined per use (TodoMVC currently turns 4k expressions into 64k document expressions and a 20 MB plan). Invariant checks go under debug_assertions only. (7) Identity: one fast structural hash (xxh3-128 or BLAKE3, which is SIMD and roughly 5-10x SHA-256 on this non-SHA-NI CPU) over the final plan, computed lazily when a cache key or export needs it. (8) Incremental: per-definition content hash, then per-SCC solved schemes kept across edits. An edit re-parses one unit, re-solves only SCCs whose inputs changed, backdates unchanged schemes, and relowers affected plan regions. Measurement design: keep phase spans as a flat thread-local ring of (id, start, end) always on (cheap), keep the work counters, and ship a repo-owned sampler that does not need perf events (the gdb/MI approach used here, or a profiling build profile with force-frame-pointers plus a perf_event_open user-only sampler, which paranoid=2 permits for own children), so attribution never depends on a system setting.
## speed_ceiling
Estimates, not measurements, built from the measured essential shares. Parse: lex/AST measured at about 4 ms (TodoMVC) and about 17 ms (NovyWave) inside today's 18/66 ms parse phases; a lean parser with no route SHA-256, no manifest and fused validation is about 3-5 ms and 10-15 ms. Typecheck: today 379 ms (TodoMVC diagnostics) and 468 ms (NovyWave diagnostics). With per-definition schemes, TodoMVC's 30x call-path expansion disappears: 4,081 expressions x about 10 constraints x about 150 ns is about 6 ms, and NovyWave's 15,650 x 10 x 150 ns is about 25 ms. Allowing 2-3x for selector-driven refinement and diagnostics gives about 10-20 ms TodoMVC and about 40-60 ms NovyWave. Diagnostics totals are then about 15-25 ms and about 50-75 ms, against budgets of 75 and 250. Verified back half: today TodoMVC semantic+backend+plan is 163+89+92 = 344 ms and NovyWave 803+222+67 = 1,092 ms. Hashing is 38% of semantic and 85-95% of plan validation, and the rest is re-projection, validation, quadratic scans and 16x plan inflation. A single lowering pass over about 4.5k/16k semantic nodes at about 1-2 us per node is about 10-30 ms TodoMVC and about 30-60 ms NovyWave. Verified totals are then about 30-60 ms and about 80-150 ms, against budgets of 300 and 1000. Counter: about 1-2 ms both intents, since today's 7.4/16.2 ms is 63% incidental. Warm edit-to-diagnostics on TodoMVC with per-SCC reuse: parse one unit plus re-solve the dirty SCCs is about 1-5 ms, against a 16.7 ms budget. For contrast, deleting only today's plainly incidental work without changing the kernel gives TodoMVC diagnostics about 343 ms (budget 75), TodoMVC verified about 536 ms (budget 300), NovyWave diagnostics about 425 ms (budget 250) and NovyWave verified about 1,030 ms (budget 1000). The kernel design (T6 in the plan, 'research, not scheduled') is the binding constraint for every diagnostics budget.

## representation_critique
- structure: Cryptographic content digests (SHA-256 over canonical CBOR) as the identity for expressions, definitions, image rows, manifests and plans | critique: Identity is computed by hashing serialized structure, not assigned during construction. That costs 25-46% of verified time on a CPU without SHA-NI, and it forces a CBOR encoding step (ciborium Encoder::push is 1.8% self on NovyWave). | better: Dense u32 ids assigned by construction order. Structural FxHash/xxh3 only where dedup is needed. One lazy final plan hash. | evidence: strict.py and hashfam.py shares; semantic_image.rs:2658; receipt.rs:265/391; boon_parser lib.rs:9513
- structure: Kernel program as one global graph of call-path frames (compiled_call_sites) solved by an incremental retraction-capable engine | critique: It expands TodoMVC 20-30x (352 calls become 10,537 compiled call sites; 4,081 expressions become 82,451 linked operations), and each activation costs about 1.6-2.8 us. Most diagnostics time lives here. | better: Per-definition principal schemes solved bottom-up per SCC, instantiated by substitution. Demand-driven refinement only where selectors need it. | evidence: work counters; KernelSession::check is 86.7% of TodoMVC diagnostics
- structure: Equivalence classes as linked member lists (equivalence_head/equivalence_next), with consumers and dependents stored per member in Vec<Vec<_>> | critique: Every bind enumerates the whole class, which gives 18.8% self time. | better: Union-find with rank, and dependents stored at the root and merged on union (or a CSR adjacency built once). | evidence: solver.rs:4086-4131
- structure: Variant sets as unsorted vectors rebuilt on each merge | critique: The position scan per incoming tag plus re-sort plus re-intern is quadratic; synthetic scaling shows n^2.5. | better: Sorted tag-id small vectors or bitsets with linear merge; hash-consed. | evidence: term.rs:1455-1495
- structure: String-keyed BTreeMaps and structural-key linear finds across adapter layers (callable_surfaces: BTreeMap<String, Box<[CallableSurface]>>, scope bindings scanned per field) | critique: They create O(n*m) scans and memcmp-heavy comparisons (memcmp is 1.7-2.6% self). | better: Dense DefId, FieldId and BindingId indexes built once per program. | evidence: kernel_oracle.rs:5580-5599; machine_plan_backend.rs:8456
- structure: The document plan with single-use functions inlined | critique: 4,081 checked expressions become 64,482 document expressions and a 20.4 MB plan on TodoMVC, which inflates backend, hashing and export time. | better: Keep functions shared in the plan and let the runtime instantiate them. | evidence: BOON_COMPILER_LOWER_TRACE 'document artifacts expressions=64482 ... inlined_one_offs=1669'
