## key
kernel_compile
## subsystem
boon_compiler_kernel: kernel compile side (checked definitions -> constraint program), i.e. owner.rs compile path, program.rs, session.rs input construction, packed_owner/packed_call_types, definition_code/artifact_terms publication, link.rs checked linker, text.rs/abi.rs
## purpose_summary
Terms first. An 'owner' is one definition: a top-level FUNCTION, a named value or a unit root (StableCheckOwnerKey mapped to a dense KernelOwnerId). The word comes from the legacy per-owner checker in boon_typecheck. Each owner gets a 'principal' frame, meaning one type variable per expression plus fresh formal variables. That frame is the only one whose results are published (add_output only at owner.rs:15196/15204, plus first-level call roots at :20784).

compile_project_program_with_definition_facts_abi_text_and_terms (owner.rs:14966) builds ONE global ComponentProgram before any solving happens. For each UserCall node, compile_node (owner.rs:20482-20800) first calls specialize_owner. A 'specialization' is keyed by (target, static tag set per formal, initial_state_surface). Static tags come from a pre-solve syntactic analysis, infer_static_variants, which prunes unreachable WHEN arms. The call then goes one of four ways:
(a) Principal reuse, when the callee result does not depend on formals (30 calls on TodoMVC).
(b) Direct projection, when the callee result is a formal read.
(c) Emit a SummaryCall. A 'direct result summary' is interpreted type-level bytecode (KernelSummaryProgram, program.rs:92) for callees whose result cone passes direct_result_summary_supported. Callees under 128 nodes are inlined into the caller's summary (SHARED_SUMMARY_MIN_NODES, owner.rs:17502).
(d) instantiate_owner (owner.rs:17008). This allocates fresh variables for the callee's formal-dependent expressions and appends a 'residual frame': a variable map over a shared per-specialization ResidualTypeModule. It then compiles the callee's own calls recursively inside that frame.

InvocationKey (owner.rs:15391) is keyed on the caller's TypeVariableIds, so frames are shared almost never (302 of 6,091 on TodoMVC). The result is one frame per call PATH, not per call site or per definition. This is why TodoMVC's 350 syntactic user calls (checked_calls = owner_calls = 350) become 10,537 compiled calls: 4,416 direct/summary + 30 principal + 5,789 frames + 302 reused. The plan's '~2,700 syntactic calls on TodoMVC' is wrong; 2,699 is NovyWave's compiled count.

A 'requirement' is a backward constraint from how a callee uses its formal (field access, pattern domain) onto the caller's actual. Frames implement it as contextual holes plus unify operations. Summaries implement it as staged, withdrawable 'requirement sites' (solver/requirements.rs), which belong to an 'exact invocation occurrence, not a resolved input type'. 'Transfer' is the legacy name for pushing a callee's result summary into a caller. It survives only in counter names (owner_interface_plan_transfer_nodes = summary_definition_nodes) and in the K1' 'closed transfer' probe.

Flow modes (Continuous, TickPresent, ...) are solved as a second equation system, ModeProgramBuilder, again per frame.

After solving, the kernel recovers per-definition results. It alpha-normalizes and double-SHA-256-hashes every reachable term per definition (artifact_terms.rs:197), orders unions by Debug strings (artifact_terms.rs:420), and rebuilds per-call substitutions by pattern-matching the principal scheme against the solved call-site types (packed_call_types.rs:238). In other words it reconstructs HM-shaped output (a generic scheme per callable plus a substitution per call, definition_code.rs:2829) that it refused to compute up front.

link.rs (18.6k lines) does not link constraint programs. It is the post-solve 'checked linker'. It relocates definition-local packed rows into global CheckedProgram row ranges and exposes KernelSemanticInputV1 accessors for boon_semantic. Roughly 4.8k lines are row materialization, about 3.9k are Ref/iterator accessor boilerplate, 1.7k are publication/ownership plan, and the rest is the test-only rich oracle (618 lines) plus tests (932). It also pulls in order.rs (2.3k lines) via #[path].

Measured cost:
- TodoMVC diagnostics: kernel input 12 ms, compile 59 ms, solve 278 ms. The compile builds 82,451 operations from 4,081 expressions.
- NovyWave diagnostics: projection 88 ms, input 52 ms, compile 85 ms, solve 248 ms.
- NovyWave verified: post-solve publication adds packed_finalize 167 ms, receipts 51 ms and link about 65 ms.
## essential_work
- Map resolved names to definition ids and build the definition call graph (O(defs + call edges)); Boon FUNCTIONs have no annotations, so inference order must follow the call graph
- Lower each definition body once to a compact, interned, topologically ordered IR (TodoMVC 4,081 nodes over 155 definitions; NovyWave 15,650 nodes over 1,389 definitions)
- Generate and solve constraints per definition: equality, directional flow/union for LATEST/WHEN arms/collections, field and pattern projection, record/collection construction, and tag-case selection
- Compute a local fixpoint for cycles through HOLD/LATEST and for mutually recursive definitions (call-graph SCCs)
- Generalize each definition into a scheme: result type, structural requirements on formals (fields read, pattern domains), and residual tag-dependent selection (WHEN on a formal becomes a type-level match resolved at instantiation)
- Instantiate the callee scheme at each of the 350 (TodoMVC) / 1,821 (NovyWave) syntactic call sites, checking the actual against the callee's requirements and reporting violations at the call site
- Compute flow modes (a 4-point lattice) alongside types
- Publish per-expression types, per-definition schemes and per-call substitutions/provenance for boon_semantic (verified intent only), and diagnostics (both intents)

## from_scratch_design
Goal: every definition is checked once, every call site costs O(size of the callee's scheme interface), and nothing depends on call paths.

1. Representation. The lexer owns one symbol interner (u32), and those ids survive to the end: no Box<str> in any kernel IR and no text rediscovery. Per definition: `DefIr { nodes: Vec<Node> /* post-order, so already topological */, edges: CSR, formals: u16, result: NodeId, calls: Vec<(NodeId, DefId)>, content_hash: u128 }`. Keep the existing hash-consed TypeTermArena idea. Add per-term flags (ground / has-vars), a cached 64-bit structural hash, and canonical member/field order decided at intern time; that kills legacy_checked_union_order. Tag sets are ordinary VariantSet terms; there is no separate StaticVariantSet.

2. Order. Tarjan SCC over the definition call graph. Process SCCs in reverse topological order, so every callee outside the current SCC already has a final scheme.

3. Per-SCC constraint generation and solving. One pass over each definition's nodes emits about 1-3 constraints per node. The constraint forms are: eq(a,b); flow(a <= b), directional, used for WHEN/LATEST arms and collections, with Simple-sub/MLsub-style lower/upper bound lists per variable so unions only grow (monotone, no Replace, no retraction); proj(a, field -> b); pmatch(a, pattern -> b); coll(...); and case(a, arms -> b), which is resolved as soon as a's head is a known VariantSet, otherwise left residual. Type variables use union-find with Rémy levels, so generalization is O(variables in the definition) with no environment scan. HOLD/LATEST cycles and recursive SCC members are solved to a local fixpoint monomorphically; they are small.

4. Generalization. A scheme is `Scheme { params: u16, result: TermTemplate, requirements: SmallVec<(formal, TermTemplate, origin_span)>, residual: Vec<ResidualConstraint> /* unresolved case/proj on params */, provenance: bits (result arm-selected by formal tag, state-owning) }`. Simplify by polarity/co-occurrence, dropping variables that cannot reach the interface. The Theme/get dispatcher becomes one residual `case request of Material[of] -> ...` instead of hundreds of frames.

5. Instantiation at a call site:
   (a) If every actual TypeTermId is ground: look up `HashMap<(DefId, SmallVec<[TypeTermId; 4]>), InstResult { result, requirement_ok | diagnostic }>`. A miss evaluates the residual with ground inputs, which is a pure function. The reuse probe already shows 95% of closed summary calls repeating with 0 value mismatches.
   (b) Otherwise, substitute params with fresh variables and push the residual constraints. Cost is O(|residual| + |requirements|), independent of the callee body and of its callees.
   The substitution is recorded directly as the published per-call substitution. This deletes post-hoc pattern matching.

6. Diagnostics. Requirement violations are reported at the call site with the callee's requirement origin, HM-style. Errors inside a generic body are reported once per definition. A single error does not poison the revision.

7. Flow modes are a lattice component computed in the same topological pass (a mode template in the scheme), not a second equation system.

8. Publication. Per definition: expression types as scheme-relative term ids, plus the scheme. Per call: the substitution plus provenance bits. boon_semantic, which re-expands call paths itself anyway (contextual_expansion::expand_with_inherited_owner shows up in the NovyWave verified profile), addresses rows as (DefId, LocalId), so there is no global row relocation. If it needs monomorphic per-path types, it instantiates the callee's body-type template with the call's substitution, memoized on (DefId, substitution), and only on the verified path.

9. Incrementality (the warm budget). Each definition is a query keyed on (content_hash, callee scheme hashes), with early cutoff when the definition's scheme hash is unchanged. A body edit that keeps the scheme re-lowers and re-solves one SCC; callers are not rechecked.

What this deletes:
- owner.rs: the four-way UserCall dispatch; instantiate_owner, specialize_owner/_static, InvocationKey, SpecializationKey, OwnerSpecialization, ResidualModuleCache, ResidualTypeModule, compile_residual_type_module, append_residual_type_frame, allocate_invocation_owner_instance, principal_external_variables; infer_static_variants, reachable_owner_nodes, syntax_selected_call_nodes, owner_expressions_depend_on_formals, transparent_type_providers, tag_arm_guards; direct_result_summary_supported with its memo, compile_direct_result_summaries, DirectSummaryPlanCompiler (1,134 lines), canonicalize_summary_node, emit_compiled_direct_summary, per-call pattern_requirement_term; ModeProgramBuilder/ModeSource/projected_mode_variable (460 lines)/projected_collection_item_mode_variable (191 lines). That is about 8.7k compile lines reduced to about 2-3k.
- program.rs: ResidualOperationFrame, ProgramOperationRef::Residual/ResidualFrame, link_residual_operation_terms, both topology passes, initial_operation_order, KernelSummaryProgram/Node/CallInput.
- solver side (a consequence): evaluate_residual, import_frame_term, summary_call and SummaryScratch, requirements.rs stage/commit/withdraw, invalidate_requirement_cone, the reschedule epochs, and PublishMode::Replace.
- packed_call_types.rs: derive_packed_call_type_substitutions and match_call_type_pattern.
- artifact_terms.rs: the alpha-normalization proof import and legacy_checked_union_order.
- session.rs/text.rs: rich compatibility input, text rediscovery and validation walks, eager basis SHA fingerprints.
- link.rs: most of the row relocation/renumbering, leaving a thin (DefId, LocalId) accessor API.

What to keep: dense ids, the hash-consed term arena, and packed per-definition columns.
## speed_ceiling
All figures are estimates, single-threaded, cold. They assume about 2-3 constraints per IR node at 100-200 ns per constraint on hash-consed terms, and lowering at 100-200 ns per node.

TodoMVC (4,081 nodes, 155 definitions, 350 call sites; 94 theme sites over 55 distinct arguments, so most instantiations are memo hits over at most a few hundred distinct (definition, argument-type) pairs):
- lowering 0.5-1 ms
- constraint generation + solve + generalization 1-3 ms
- instantiation under 1 ms
- verified publication 1-2 ms
- total kernel 3-10 ms, versus 366 ms today (input 12 + compile 59 + solve 278 + projection 17), and ~434 ms for verified.

NovyWave (15,650 nodes, 1,389 definitions, 1,821 call sites):
- lowering 2-4 ms
- solve 5-12 ms
- instantiation 1-3 ms
- publication 2-5 ms
- total kernel 10-30 ms, versus 473 ms for diagnostics today (projection 88 + input 52 + compile 85 + solve 248) and about 800 ms for verified (+ packed_finalize 167, receipts 51, link 65).

Warm edit whose body change keeps the scheme: re-lower and re-solve one SCC plus a scheme-hash compare, 0.2-2 ms. That fits the 16.7 ms warm budget even with parse and presentation added. The current design cannot get there except for no-op edits, because callee bodies are inlined into every caller's frames.

Why this codebase is 10-100x off the ~100k lines/s ML reference in this area:
1. Work scales with call paths, not source: 20x more operations than nodes on TodoMVC, exponential in synthetic depth.
2. The solver is quadratic in frames.
3. On NovyWave, more than half the kernel time is outside the solve: building String-based input and re-interning it, SHA fingerprints, and post-hoc re-generalization with SHA-256 per term per definition.
4. Summaries replicate the path blow-up in bytecode (101,753 nodes from 15,650 expressions).

## representation_critique
- structure: InvocationKey { target, actuals: Box<[(TypeVariableId, ModeVariableId)]>, static_variants, initial_state_surface } (owner.rs:15391) | critique: It keys on variable identity, not on semantic input, so two call sites passing the same tag never share a frame (302 reuses out of 6,091). This is forced because types do not exist yet when the graph is built. | evidence: invocation_frames 5,789, reused 302 on TodoMVC; 94 Theme call sites over 55 distinct arguments | better: Key on (DefId, SmallVec<[TypeTermId; N]>) of hash-consed resolved argument types, which is possible because callees are generalized before callers are checked.
- structure: OwnerSpecialization (owner.rs:15464): four node_count-sized boxed slices plus Vec<Option<Arc<[SymbolId]>>>, cloned out of a SipHash HashMap for every compiled call | critique: It is O(callee size) memcpy and allocation per call, 42% of it wasted on early exits. The data is itself the output of shadow type analyses. | evidence: specialize_owner 14.5% of compile samples; 10,123 plan reuses, each a full clone | better: Delete it with schemes. In the interim, use Arc<OwnerSpecialization> with bitsets and FxHash.
- structure: ResidualTypeModule: a separate ComponentProgram with its own TypeTermArena, relinked into the global arena once per frame in finish() | critique: A private arena per module forces per-frame term import (program.rs:1144) and a second interning. The operations are shared, but solving is duplicated per frame. | evidence: 402 modules / 8,160 ops expand to 5,944 frames / 82,451 linked ops | better: Scheme residuals living in the global arena, instantiated by substitution with no solving duplicated per instantiation.
- structure: Rich kernel input KernelOwnerNodeKind / KernelOwnerEdgeRole with Box<str> names, rich boon_checked::Type and derive(Serialize, Hash) (owner.rs:141-340) | critique: It is a String-heavy tree built by boon_compiler (prepare_kernel_project_projection: 17 ms TodoMVC / 88-101 ms NovyWave), then re-interned, validated, SHA-fingerprinted through derive(Hash) and packed. That is three representations before constraint generation. | evidence: session.rs:86-133; kernel_oracle.rs:620 | better: The parser/resolver emits the packed per-definition IR directly with interned SymbolIds and PathIds.
- structure: Global ComponentProgram with CSR dependencies/consumers over every frame's operations plus a global initial topological order | critique: It is a whole-program schedule for what is really a forest of small per-definition DAGs. It needs 5-6 passes to build and makes the whole project one failure domain (a failed solve is terminal for the revision, session.rs:851-858). | evidence: program.rs:1132-1301; 26,226 work items on TodoMVC | better: Per-definition post-order IR solved per SCC; failures stay local to a definition.
- structure: Artifact term proofs: two SHA-256 digests per reachable term per definition, plus a Debug-string union order (artifact_terms.rs:197-440) | critique: It uses a cryptographic hash as the identity mechanism inside one process, and string formatting as the canonical order. | evidence: 25% of NovyWave finish_graph samples in sha256; 4.5% in Debug formatting | better: Hash-consed ids are identity in-process. - structure: KernelSummaryProgram bytecode with Invoke nodes and an inline threshold of 128 nodes (owner.rs:17502) | critique: Inlining small callees duplicates bytecode per caller, which grows exponentially with depth. Evaluation allocates fresh holes per invocation and has no per-tuple memo. | evidence: synthetic 1,244 -> 8,424 summary nodes for depth 8 -> 11; NovyWave 101,753 nodes | better: One scheme per definition, referenced (never inlined), with memoized ground instantiation.
- structure: link.rs global row relocation (KernelCheckedRowRange::resolve, rebase_definition_spans) plus about 3.9k lines of Ref/iterator accessors | critique: Definition-local ids are renumbered into global dense ids for a legacy CheckedProgram shape. Most of the file is accessor boilerplate over packed columns. | evidence: rows 17.2/60.1 ms verified; link.rs structure: layout impl 4,827 lines, Ref/iterators ~3,930 | better: (DefId, LocalId) addressing consumed directly by boon_semantic; a thin generic column-view API.
