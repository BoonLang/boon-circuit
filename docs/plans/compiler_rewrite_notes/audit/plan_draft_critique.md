=========== CONSISTENCY: (a) whether the plan matches owner decisions D1
OVERALL: Most of the cited numbers check out. I re-derived fixture line counts (140 / 3,576 / 11,926), crate sizes (typecheck 109k, semantic 97k, kernel 81k, checked+ir+verify+compilation_db 17.7k), the Theme call sites (94 in 6 files; NovyWave 84+60), theme lines (2,444), plan docs (12 files, 13.1k lines, excluding this plan), 44 evidence files / 648 KB, 7 handoff gates, the classifier's 15.8k lines, the xtask 25,023 lines, and the profile figures (390/790, 526/1,870, 25/31/39% SHA, 157 MB hashed, 10,537 compiled call sites, 82,451 / 169,680 / 4,081 / 416k / 1.34M, 5/22 SCC nodes, 155/1,389 definitions, 680 PlanError sites). The real problems are elsewhere. First, the plan quietly changes several owner decisions. The biggest is a name-scoping change: under it `[x: x]` copies the outer `x`. The plan presents this as following from D9, but it overturns the documented rule (LANGUAGE_SEMANTICS.md:216-219) and makes the 'field self-reference' diagnostic that D6 explicitly lists impossible. Second, the plan never checks D9's strict cycle rule against the product examples. As written, the rule rejects the Cells spreadsheet (a derived row cycle guarded by Dependency/catch_cycle), yet the plan says Cells stays unchanged. It also rejects TodoMVC's completed/all_completed cycle. Third, several semantic and syntax choices are presented as settled even though the design notes raised them as owner questions: layout rules and tabs, `--` inside TEXT, comparisons not chaining, bare-or-tagged tags, unused parameters as errors, open parameters on user functions. The §11 preamble makes this worse: it adopts semantic defaults unless the owner objects. Fourth, there are internal contradictions. 'MachinePlan v11 frozen, API-level runtime changes only, exact differential' clashes with the snapshot-semantics runtime fix, the cursor behaviour change and the PERSISTENCE_FORMAT_VERSION bump. 'No cryptographic hashing' clashes with v11's SHA-256 identity constructors. The checker is said to own diagnostics that Phase A actually emits. The persistence schema ignores stateful LATEST and Bool/toggle state. There are two different 'pinned oracle' definitions. Q18's identity scope contradicts the hot-reload identity claims and the O3/O5 determinism oracles. The schedule numbers are internally wrong: the critical path skips P3 and P6, the effort total is below the sum of the phases, and the calendar estimate is shorter than the critical path. None of this invalidates the architecture, but the owner should not approve the plan as 'settled decisions plus defaults' until the missing questions below are asked and these sections are reconciled.
